Stress tested the template against more than one set of answers.

- `ctt.toml` now generates three feedstocks rather than one: the defaults, a hyphenated
  and numbered dataset name, and an answer set full of quotes, apostrophes and accents.
- The contract tests run once per generated feedstock and derive what they expect from
  `.copier-answers.yml`, so nothing is pinned to the word "example" any more.
- New tests parse the generated TOML and YAML and check the answers survive the trip,
  compare the feedstocks against each other so example inputs and resource namespaces
  cannot collide, and assert no generated file carries unrendered template syntax.
- The `copier.yaml` questions, validators and tasks are covered directly, including a
  table of names and URLs each validator has to accept or reject.
- `cache_key.py` is covered end to end: near miss literals, unparseable build files,
  the outputs written for the step, and agreement with each generated build file.

Recording is now covered in CI rather than only on a developer machine.
CI generates the fixtures before running the tests, so the feedstocks have the lock file
they sync against. Without it the recording tests skipped and CI passed regardless.
The tests also read `bundle/manifest.lock` now instead of checking the directory exists,
so a recorded bundle has to carry the right book, both registered resources, the
provenance edge between them, and tracking identifiers derived from the project URL.
