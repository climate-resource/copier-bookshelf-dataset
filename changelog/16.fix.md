Seeded the example input with `dataset_name`, so every generated feedstock produces distinct bytes.

The example data was a fixed literal, identical in every generated feedstock,
and the processed output derives from it, so both registered resources hashed the same everywhere.
Registration deduplicates on content, so the second feedstock to publish into a deployment
aliased onto the first feedstock's resources and then failed to attach them:
`Resource '...' is attached to a published book and cannot be re-pointed`.

The example now carries a `dataset` column naming the feedstock,
and the template computes `input_sha256` from those bytes rather than hardcoding it,
so the build stays deterministic and hash verified.
