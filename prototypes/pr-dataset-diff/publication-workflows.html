    All options upload preview content on every push, retain immutable snapshots, and keep a stable PR overview. GitHub releases and tags are not required. Publication records an edition only for changed books; an unchanged book keeps its edition. The prototype treats metadata edits as reviewable, while final edition behaviour must follow Bookshelf’s publication rules.

    Workflows 1 and 2 propose publishing the changed set together, across volumes. That coordination needs implementation; it is not an existing cross-volume transaction. Workflow 3 deliberately allows partial publication and records each outcome. Retrying must reuse completed outcomes.

    Before publishing, verify the merged tree produces the reviewed content and recheck the pinned baseline editions. Changed merge output, changed publication baselines or newer staged work should block stale publication and require another comparison. These concurrency checks are design requirements, not simulated here.

    The PR declares a desired set of volume/version targets. A target missing from a later push is withdrawn from this proposal, not deleted from the catalogue. New volumes need explicit creation permission; previews do not silently create public catalogue entries. Preview visibility follows dataset access, even when the GitHub PR is public.

    No real APIs, permissions, publication, comments or GitHub events are connected. Charts and changes use small synthetic arrays. “Review” represents a data sign-off; GitHub branch protection still controls merging.
